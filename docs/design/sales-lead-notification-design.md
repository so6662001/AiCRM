# 销售线索实时提醒系统 - 产品设计方案

## 一、需求背景

当客户（采购员）在平台上查询资源时，如果查询到了某个商家的商品，这个查询行为会产生一条**销售线索**。我们需要将这条线索**及时推送给对应的销售员**，让销售员能够：

1. **实时感知** —— 第一时间知道有客户在关注自己的商品
2. **直观查看** —— 清晰看到线索的关键信息（谁在看、看了什么）
3. **关闭后可回溯** —— 关闭提醒后，仍然能在固定入口找到历史线索

---

## 二、线索展示位置总览

根据销售员的使用场景，线索提醒需要覆盖以下 **三个页面**，并采用 **三层提醒机制**：

| 层级 | 组件 | 出现位置 | 作用 |
|------|------|----------|------|
| 第一层 | 🔔 顶部导航栏消息铃铛 | 所有页面（全局） | 持久入口，红点/数字角标提示未读数 |
| 第二层 | 📋 右下角浮动弹窗 | 所有页面（全局） | 实时推送，新线索到达时自动弹出 |
| 第三层 | 📊 工作中心线索看板 | 销售工作中心页面 | 完整的线索管理列表，支持筛选/跟进 |

---

## 三、各层级详细设计

### 3.1 第一层：顶部导航栏 —— 消息铃铛（全局常驻）

#### 放置位置

在顶部导航栏的**右侧区域**，位于用户头像/昵称的**左边**，与现有的「找钢材」「上传库存」等操作按钮保持同一行。

```
┌─────────────────────────────────────────────────────────────────────┐
│ Logo  首页  招商入驻  广告投放  关于我们  联系我们  分站              │
│                                    找钢材  上传库存  🔔(12) 👤 黄好匠│
│                                                      ↑              │
│                                              消息铃铛（带角标）       │
└─────────────────────────────────────────────────────────────────────┘
```

#### 交互设计

- **未读状态**：铃铛图标右上角显示红色数字角标（如 `12`），表示有 12 条未读线索
- **无未读时**：仅显示铃铛图标，不显示角标
- **点击铃铛**：展开下拉面板，显示最近的线索列表（最多展示 10 条）

#### 下拉面板内容

```
┌──────────────────────────────────────┐
│  📋 销售线索                 全部已读  │
│ ─────────────────────────────────── │
│  🔵 天津某建材公司 查看了您的        │
│     「镀锌带方管 10*20*0.6」        │
│     2 分钟前                        │
│ ─────────────────────────────────── │
│  🔵 唐山某贸易公司 查看了您的        │
│     「镀锌带方管 10*20*0.8」        │
│     15 分钟前                       │
│ ─────────────────────────────────── │
│  ⚪ 北京某工程公司 查看了您的        │
│     「镀锌带方管 10*20*1.1」        │
│     1 小时前                        │
│ ─────────────────────────────────── │
│           查看全部线索 →             │
└──────────────────────────────────────┘
```

- 🔵 蓝色圆点 = 未读线索
- ⚪ 灰色圆点 = 已读线索
- 点击「查看全部线索 →」跳转到销售工作中心的线索看板

## 五、技术实现要点

### 5.1 实时推送方案

| 方案 | 说明 | 推荐度 |
|------|------|--------|
| **WebSocket** | 建立长连接，服务端主动推送新线索 | ⭐⭐⭐⭐⭐ 推荐 |
| SSE (Server-Sent Events) | 服务端单向推送 | ⭐⭐⭐⭐ 备选 |
| 轮询 (Polling) | 每 10-30 秒请求一次 | ⭐⭐⭐ 简单但体验差 |

**推荐使用 WebSocket**，保证线索的实时性，销售员能在客户查询的第一时间收到通知。

## 六、用户体验细节

### 6.1 提醒频率控制

- **合并策略**：同一客户在 5 分钟内多次查询同一商品，合并为 1 条线索
- **免打扰**：支持设置免打扰时段（如深夜 22:00 - 08:00 不弹窗，但铃铛仍然累计）
- **优先级**：高意向客户（多次查看、查看多个产品）的线索标记为⭐高优先级，优先弹窗

### 6.2 关闭后可回溯

用户关闭浮动弹窗后，线索不会消失：
1. **铃铛下拉面板** 中仍然可以看到（标记为已读状态）
2. **线索中心 Tab** 中始终保留完整记录
3. 线索中心 Tab 上的**角标数字**提示未处理数量

### 6.3 浏览器通知（可选增强）

当销售员未聚焦在平台页面时，可通过 **浏览器原生通知 (Notification API)** 推送桌面提示：

```
┌──────────────────────────────┐
│ 🔔 货袋子 - 新线索            │
│ 天津某建材有限公司正在查看    │
│ 您的「镀锌带方管 10*20*0.6」 │
│                    [查看]     │
└──────────────────────────────┘
```

## 七、设计总结

| 场景 | 组件 | 目的 |
|------|------|------|
| 销售员在任何页面 | 🔔 顶部铃铛 + 角标 | 始终可见未读数，随时点击查看 |
| 新线索到达时 | 📋 右下角浮动弹窗 | 即时感知，快速决策是否跟进 |
| 主动管理线索 | 📊 工作中心-线索中心Tab | 完整列表，筛选/跟进/统计 |
| 不在平台页面时 | 💻 浏览器桌面通知 | 即使切换了标签页也不错过 |

**核心原则：三层提醒，层层递进，确保销售员不错过任何一条有价值的线索。**
