# AiCRM 系统架构设计文档

## 1. 项目概述

AiCRM 是一个**平台级多租户 CRM 系统**，核心功能包括客户管理、线索管理、商机管理、线索分配、ERP 集成、外勤管理及 AI 智能分析。系统需支持 **100 万并发量**。

### 1.1 产品形态

| 端 | 技术栈 | 说明 |
|---|---|---|
| PC 端 | Vue3 | 作为模块集成到现有产品中 |
| 移动端 | UniApp | 独立 APP，支持 Android/iOS |
| 后端服务 | Java (Spring Boot / Spring Cloud) | 微服务架构 |

### 1.2 核心业务模块

```
AiCRM
├── 线索管理（Leads）
├── 客户管理（Customers）
├── 商机管理（Opportunities）
├── 线索分配（Lead Distribution）
├── 客户跟进（Follow-up）
├── ERP 集成（ERP Integration）
├── 外勤管理（Field Work）
│   ├── 签到/打卡（Check-in）
│   ├── 拜访管理（Visit Management）
│   ├── 电话录音采集与 AI 分析
│   └── 任务管理（Task Management）
└── 平台管理
    ├── 多租户管理（Multi-Tenant）
    ├── 组织架构（Organization）
    ├── 权限管理（Permission）
    └── 系统配置（Configuration）
```

## 3. 多租户架构设计

### 3.1 租户隔离策略

采用 **共享数据库 + 租户字段隔离** 方案，适合 SaaS 平台级应用：

```
┌─────────────────────────────────────────────────┐
│              多租户隔离策略                        │
│                                                   │
│  方案：共享数据库 + tenant_id 字段隔离              │
│                                                   │
│  ┌───────────────────────────────────────────┐    │
│  │         所有业务表增加 tenant_id 字段        │    │
│  │                                           │    │
│  │  SELECT * FROM customer                   │    │
│  │  WHERE tenant_id = #{currentTenantId}     │    │
│  │  AND ...                                  │    │
│  └───────────────────────────────────────────┘    │
│                                                   │
│  数据隔离保障：                                    │
│  1. MyBatis 拦截器自动注入 tenant_id 条件           │
│  2. 所有写操作自动填充 tenant_id                    │
│  3. 框架层面禁止跨租户数据访问                      │
│  4. 大租户可独立数据库（可选升级路径）               │
└─────────────────────────────────────────────────┘
```

### 3.2 租户上下文传递

```
请求流入 → Gateway 解析租户标识（Header/域名/Token）
         → 注入 TenantContext（ThreadLocal）
         → 服务间调用自动传递（Feign Interceptor）
         → MyBatis 拦截器自动过滤
```

### 3.3 租户数据模型

```
tenant (租户表)
├── id                    -- 租户ID
├── tenant_code           -- 租户编码（唯一）
├── tenant_name           -- 租户名称
├── status                -- 状态（启用/禁用/试用）
├── edition               -- 版本（基础版/专业版/企业版）
├── max_users             -- 最大用户数
├── expire_date           -- 到期时间
├── db_config             -- 独立数据库配置（可选）
├── storage_quota         -- 存储配额
└── erp_config            -- ERP 连接配置（JSON）
```

## 4. 权限与组织架构设计

### 4.1 鉴权方案

鉴权对接现有系统 API 接口：

```
┌──────────┐    ┌──────────────┐    ┌──────────────┐
│  CRM 前端 │───▶│  CRM Gateway  │───▶│ 现有鉴权系统  │
│          │    │  (鉴权过滤器) │◀───│ (Token验证)   │
│          │    └──────┬───────┘    └──────────────┘
│          │           │
│          │    ┌──────▼───────┐
│          │    │  CRM 权限服务  │   ← CRM 内部的数据权限
│          │    │  (数据权限)    │     与功能权限控制
│          │    └──────────────┘
└──────────┘
```

- **身份认证**：调用现有系统 API 完成 Token 验证
- **功能权限**：CRM 内部基于 RBAC（角色-权限）模型管理
- **数据权限**：CRM 内部基于组织架构层级控制

### 4.2 数据权限模型

```
数据可见性规则：
┌─────────────────────────────────────────────────────┐
│                                                       │
│  总经理/管理员                                         │
│  └── 可查看：所有数据                                  │
│                                                       │
│  销售总监                                              │
│  └── 可查看：本部门及下属部门所有数据                    │
│                                                       │
│  销售经理                                              │
│  └── 可查看：本团队及下属成员数据                        │
│                                                       │
│  销售员                                                │
│  └── 可查看：仅自己负责的数据                           │
│                                                       │
│  运营人员                                              │
│  └── 可操作：添加线索、分配线索                         │
│  └── 可查看：所有线索（不含商机详情）                    │
│                                                       │
└─────────────────────────────────────────────────────┘
```

### 4.3 组织架构模型

```
organization (组织架构)
├── id
├── tenant_id
├── parent_id             -- 上级组织
├── org_name              -- 组织名称
├── org_type              -- 类型（公司/部门/团队）
├── org_path              -- 层级路径 (如: /1/3/7/)
├── leader_user_id        -- 负责人
└── sort_order

user_role (用户角色)
├── user_id
├── role_id               -- 角色：管理员/销售总监/销售经理/销售员/运营
├── tenant_id
└── org_id                -- 所属组织

role_permission (角色权限)
├── role_id
├── permission_code       -- 权限编码
├── data_scope            -- 数据范围：ALL/DEPT_AND_BELOW/SELF
└── tenant_id
```

### 5.1 线索管理 (Lead Management)

```
线索生命周期：
┌───────┐    ┌───────┐    ┌──────┐    ┌───────┐    ┌──────┐
│ 新线索 │───▶│ 已分配 │───▶│ 跟进中│───▶│ 已转化 │───▶│ 成交  │

                 ▼

            └───────┘
```

**线索来源**：运营手动录入、批量导入、API 对接（广告平台等）

**核心字段**：
- 线索基本信息（姓名、电话、公司、来源渠道）
- 跟进状态、分配状态
- 意向等级（A/B/C/D）
- 线索评分（可配规则自动评分）

| `aicrm-gateway` | API 网关 | 路由、鉴权、限流、租户识别 |
| `aicrm-lead` | 线索服务 | 线索 CRUD、线索分配、公海池 |
| `aicrm-customer` | 客户服务 | 客户 CRUD、客户查重、客户转移 |
| `aicrm-opportunity` | 商机服务 | 商机 CRUD、阶段管理、销售漏斗 |
| `aicrm-followup` | 跟进服务 | 跟进记录、拜访管理、签到 |
| `aicrm-task` | 任务服务 | 工作任务、任务分配、完成跟踪 |
| `aicrm-erp` | ERP 集成服务 | ERP 数据同步、字段映射、适配器 |
| `aicrm-ai` | AI 分析服务 | 录音转写、内容分析、违规检测 |
| `aicrm-fieldwork` | 外勤服务 | 打卡签到、位置采集、录音采集 |
| `aicrm-notify` | 通知服务 | 消息推送、短信、邮件、APP通知 |
| `aicrm-tenant` | 租户服务 | 租户管理、套餐管理 |
| `aicrm-org` | 组织权限服务 | 组织架构、角色权限、数据权限 |
| `aicrm-file` | 文件服务 | 文件上传/下载、OSS管理 |
| `aicrm-audit` | 审计服务 | 操作日志、审计追踪 |
| `aicrm-report` | 报表服务 | 销售报表、业绩统计、数据分析 |
